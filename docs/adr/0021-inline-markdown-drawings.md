# ADR 0021: Inline Markdown drawings

## Status

Accepted on 2026-10-02 by operator request ("add the ability to draw in the
Markdown; base it on the official Tauri API"). Adds an editor capability; it
changes no schema, Workspace, IPC, persistence, or deletion contract.

## Context

People who capture notes for agents sometimes need a quick sketch: an arrow
between two boxes, a circled area, a rough flow. Charon's Note is one Markdown
body in a user-owned file, and its Preview deliberately creates no image or
resource-loading element. A drawing feature must keep the Note readable as
plain text, keep `Copy as Markdown` byte-exact, add no network access, and not
weaken the Preview's safety rules.

## Decision

1. A drawing is ordinary Markdown text in the Note body: one fenced code block
   whose info string is exactly `svg` and whose content is a small SVG document
   generated by Charon and marked `data-charon-drawing="1"`.
2. Persistence uses the existing Workspace command that saves a Note body,
   invoked through `@tauri-apps/api/core` by the existing workspace client.
   The drawing dialog only edits the editor's draft through the draft reducer,
   so autosave, dirty guards, and the close guard are unchanged. React never
   touches files.
3. Input uses standard Pointer Events inside the Tauri webview: pointer capture,
   coalesced events where available, a live stroke mutated through a ref with
   no React state per move, and one commit per stroke on pointer up or cancel.
   No third-party drawing library and no new Tauri plugin.
4. The editor gains a Draw button beside Markdown help. In Write it inserts at
   the caret, or edits the drawing whose block holds the caret. Each top-level
   drawing in Preview offers Edit drawing; one inside a quote, list item, or
   footnote is shown without it. Editing replaces exactly that block, matched
   by its index among top-level drawings and its canonical content; if it no
   longer exists, the result is inserted as a new block and nothing else is
   replaced. A new block never lands inside another fence: a caret in a closed
   fence moves past it, and a fence that is never closed takes the block
   before its opening line. Fences are located as the Preview renderer groups
   lines into blocks (amended 2026-10-02 after review: a quoted or listed
   drawing edited from Preview used to be duplicated, and a block inserted
   into an unclosed final fence became its content).
5. The dialog offers pen and stroke eraser, five inks, three widths, undo,
   redo, and an undoable Clear. Cancel or Escape with unsaved strokes first
   asks inline whether to discard them.

### Format v1

The root is `<svg>` with exactly `xmlns="http://www.w3.org/2000/svg"`,
`viewBox="minX minY w h"` (finite numbers, 0 < w, h ≤ 4096), `width` and
`height` equal to `w` and `h`, and `data-charon-drawing="1"`. Attribute order
is free when parsing and fixed when serializing. Children are 0-2,000
self-closing `<path>` elements separated only by whitespace. A path has `d`
using only absolute `M`, `L`, and `Q` with plain decimal numbers (at most
20,000 per path), `fill="none"`, `stroke` (`currentColor` or lowercase
`#rrggbb`), `stroke-width` 0.5-48, round caps and joins, and optional
`stroke-opacity` 0-1. The serialized block is at most 256 KiB.

The ink palette is stored content data: `currentColor` (default, the theme text
colour), Lavender `#8f8be8`, red `#e5484d`, blue `#3e63dd`, and green
`#30a46c`; widths are 2, 4, and 8 logical units. Ink colours are user content
stored in the Note, not theme roles, so they are an explicit exception to the
rule against raw palette values in product components; the drawing dialog
shows them as swatches. Pointer input maps into a
`0 0 960 600` logical space. Saving rounds coordinates to one decimal, drops
points closer than 1.5 units, smooths with quadratic curves through midpoints
(a tap becomes a dot), and crops the viewBox to the strokes plus 16 units and
half the stroke width, clamped to the logical space.

### Safety

Charon never injects drawing text as HTML and keeps `allowHtml` disabled. A
hand-written tokenizer accepts only printable ASCII without `&`, so no entity,
character reference, DOCTYPE, comment, CDATA, processing instruction, text
node, or unknown element or attribute survives; any of them makes the block an
ordinary code block. Preview re-creates `<svg>` and `<path>` React elements
from parsed numbers and enumerated strings only. No script, event attribute,
`href`, `style`, `image`, `use`, or `foreignObject` can reach the DOM, and a
drawing causes no resource request.

### Privacy

A drawing stays in the local Note body and its Workspace file. Drawing makes no
network request. `Copy as Markdown` includes the SVG text exactly as stored,
which agents and other Markdown tools can read. Search excludes drawing source
so coordinates never match a query; headlines show a localized Drawing label.
Deleting the Note deletes its drawings through the existing contract.

## Alternatives rejected

- Attachment PNG or SVG files: Preview would need Attachment reads, and the
  body would need references that can dangle or drift from managed files.
- Raw inline HTML `<svg>` in Markdown: unsafe to render and fragile for other
  Markdown tools; Charon would have to enable HTML.
- Third-party canvas or whiteboard libraries: unnecessary weight and surface
  for strokes, eraser, and undo that Pointer Events and SVG already cover.
- A native Tauri plugin for ink: no platform capability is needed beyond the
  webview's Pointer Events.

## Consequences

- Drawings are versioned, backed up, synchronized, copied, and deleted with
  their Note, with no new cleanup path.
- Other Markdown tools show a readable `svg` code block rather than a picture.
- Hand-edited blocks that leave the whitelist render as code until fixed.
- The format is versioned by its marker; a later format needs a new marker
  value and an ADR.
- Drawing requires a pointer, pen, or touch; the dialog states this, and its
  controls remain keyboard reachable.

## Revisit when

Revisit if users need richer shapes, text labels, or pressure, if drawings
grow beyond the 256 KiB block limit in practice, or if drawings nested in
lists or quotes need direct editing; editing finds top-level fences only,
although Preview renders any valid block, and Preview offers Edit drawing only
for those.
