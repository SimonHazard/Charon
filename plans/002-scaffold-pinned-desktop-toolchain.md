## Why this matters

Every later plan depends on one reproducible workspace containing the desktop
application, static preview site, and shared visual contract. Exact versions and
one root command surface prevent vibe coding agents from drifting into separate
lockfiles, duplicated theme values, incompatible package managers, old shadcn
primitives, or accidental cross-app imports.

## Current state

- Plan 001 supplies documentation only.
- There is no JS or Rust project, workspace, package manager lock, Tauri config,
  Astro config, shared theme package, router, linter, formatter, test runner, or CI.
- The approved version ledger is in `plans/README.md`.
- TypeScript 7.0.2 is the native Go compiler release. Use Biome, not ESLint or a
  TypeScript-compiler-API-based lint plugin.
- `@astrojs/check 0.9.10` declares TypeScript 5/6 support, so the Astro package
  temporarily pins TypeScript 6.0.3. Desktop remains on TypeScript 7.0.2.

## Steps

### Step 1: Create the Bun workspace boundary

Confirm Bun, Rust stable, Node 22.12+ for Astro tooling, the platform C toolchain,
and Tauri prerequisites. Create a private root `package.json` with workspaces
`apps/*` and `packages/*`, an exact `packageManager`, and no runtime dependencies.
Create `tsconfig.base.json`, root Biome config, and root scripts that delegate to
named workspaces. There is one root `bun.lock`; nested lockfiles are forbidden.

Required workspace names are `@charon/desktop`, `@charon/site`, and
`@charon/theme`. Root scripts include `dev:desktop`, `dev:site`, `preview:site`,
`build:desktop`, `build:site`, `test:desktop`, `test:site`, aggregate `build`,
`typecheck`, `test`, `lint`, `check`, `tauri:dev`, and `tauri:build`. Use Bun
workspace filters or `--cwd` explicitly; do not rely on whichever package
happens to be current.

**Verify**: `bun pm ls --all` -> three Charon workspaces after later scaffolds;
`find . -name 'bun.lock' -print` -> exactly `./bun.lock`.

### Step 2: Scaffold the desktop and site with their official CLIs

Run the exact Desktop scaffold command from the table. If TanStack CLI rejects
`--intent`, `--force`, or `-y`, inspect pinned help and use only an equivalent
documented flag. Select Router-only SPA, Vite, React, TypeScript, and Bun. Preserve
`.git`, `plans/`, and Plan 001 documents.

Run the exact Site scaffold command. If a flag changed, inspect
`bunx --bun create-astro@5.2.3 --help` and select the official minimal template,
strict TypeScript, no Git, and no install. Do not add React to Astro. Normalize
both generated packages into the root workspace and delete any nested lockfile.

**Verify**: `test -f apps/desktop/vite.config.ts && test -d apps/desktop/src/routes && test -f apps/site/astro.config.mjs && test -f apps/site/src/pages/index.astro` -> exit 0; `rg -n "@tanstack/react-router" apps/desktop/package.json` and `rg -n '"astro"' apps/site/package.json` -> matches.

### Step 3: Pin workspace dependencies and the split TypeScript toolchain

Replace all direct semver ranges with exact versions from `plans/README.md`.
Desktop receives Router, Router plugin, Hotkeys, Virtual, Tauri API/plugins,
React, Vite, TypeScript 7.0.2, Tailwind Vite, Paraglide, Base UI, Tabler icons,
shadcn runtime dependencies, `motion` 12.43.0, Zod, Vitest, Testing Library,
jsdom, Playwright, and Biome as appropriate. Add Tauri process only for the
updater restart path. Do not add Charts yet; Plan 010 owns it. Motion is a
desktop dependency only; do not add React, Motion, or an island to Astro and do
not add a runtime dependency to `@charon/theme`.

Site receives Astro 7.1.6, `@astrojs/check 0.9.10`, sitemap 3.7.3, sharp 0.35.3,
Tailwind 4.3.3, Tailwind Vite 4.3.3, and TypeScript 6.0.3. Record the TypeScript 6
exception in the package and ADR 0004. Confirm `astro check` resolves the site's
local compiler, not hoisted TypeScript 7. Root tooling may use TypeScript 7 but
must not trick Astro Check into an unsupported compiler.

Configure Biome for two-space indent, single quotes in JS/TS, organized imports,
Astro support if stable in the pinned release, and generated exclusions for
`apps/desktop/src/routeTree.gen.ts` and `apps/desktop/src/paraglide/**`.

**Verify**: `bun install && bun install --frozen-lockfile` -> exit 0; `rg -n '"\^|"~|latest' package.json apps/*/package.json packages/*/package.json` -> no direct-dependency matches; `bun --cwd apps/desktop x tsc --version` -> `7.0.2`; `bun --cwd apps/site x tsc --version` -> `6.0.3`.

### Step 4: Configure the desktop web stack and localization

Configure `apps/desktop/vite.config.ts` with TanStack Router, Paraglide, React,
and Tailwind plugins in documented order. Use file routes and generated
`apps/desktop/src/routeTree.gen.ts`. Configure Paraglide project
`./project.inlang`, output `./src/paraglide`, declarations on, locales EN/FR,
base EN, and strategy `localStorage` then `baseLocale`.

Seed only smoke messages. Configure Vitest jsdom, setup file, and `@/* -> src/*`
within desktop. Keep English deterministic on first launch.

**Verify**: `bun run typecheck && bun run test:desktop` -> exit 0 and a localized route smoke passes; `rg -n 'baseLocale.*en|localStorage' apps/desktop/project.inlang apps/desktop/vite.config.ts` -> relevant matches.

### Step 5: Initialize shadcn Base UI inside desktop only

Run the pinned shadcn docs command from `apps/desktop`, then initialize the
Base UI `base-nova` preset or nearest documented Base UI preset. Configure
Tailwind v4, semantic variables, and the supported Tabler option. If Tabler is
unsupported, record the deviation rather than hand-converting generated files.

Add only `button`, `field`, `input`, `separator`, `tooltip`, and the Base UI
`toast` component. Base UI composition uses `render`, never `asChild`. Do not run
shadcn in `apps/site` and do not create a shared React component package.

**Verify**: `cd apps/desktop && bunx --bun shadcn@4.16.0 info` -> Base UI and Tailwind v4; `rg -n 'asChild' apps/desktop/src/components/ui` -> no matches; `test ! -e apps/site/components.json` -> exit 0.

### Step 6: Create the framework-neutral theme package and Astro smoke page

Create `@charon/theme` with explicit CSS exports for `tokens.css`, `motion.css`,
and `index.css`. The scaffold contains only semantic token names and minimal
light/Solarized/dark placeholders that Plan 004 will finalize. It has no build
step and no framework dependency. Both apps import its package export, never a
relative path into `packages/theme/src`.

Configure Astro static output, sitemap integration, Tailwind via Vite, EN at `/`
and FR route support, and a minimal smoke page using shared background/text/accent
tokens. Do not add final marketing sections or media. Disable Astro telemetry in
CI/documented setup. Use `astro:assets` for the smoke image pipeline.

**Verify**: Site check command exits 0; `bun run build:site` produces static
`apps/site/dist`; `rg -n "@charon/theme" apps/desktop apps/site` -> imports in both;
`rg -n "react|tauri|base-ui" packages/theme/package.json` -> no matches.

### Step 7: Initialize the Tauri 2 shell under desktop

Initialize Tauri in `apps/desktop` without replacing Vite. Set product name
`Charon`, identifier `dev.charon.app`, correct monorepo-relative frontend dev and
build commands, and one main window. Add exact Rust dependencies from the ledger.
Register single-instance and window-state; keep minimal stubs for global shortcut,
fs, dialog, clipboard, updater, and process.

Create a minimal capability for the main window. Do not grant broad fs, shell,
or updater access. Keep Rust `lib.rs` shared and `main.rs` tiny. Ensure Tauri's
before-build command builds desktop only, never Astro.

**Verify**: Rust quality and Desktop build commands exit 0. Launch
`bun run tauri:dev`; the main window opens the Router route, then stop it.

### Step 8: Normalize generated agent guidance

Inspect `.tanstack/**`, `.agents/**`, and `.codex/**`. Keep only repo-relative,
non-secret guidance consistent with root `AGENTS.md`. State workspace ownership,
root commands, the TypeScript split, shared-token-only rule, and which app an
agent may modify. Do not alter global user skills.

**Verify**: `rg -n "pnpm|npm install|yarn|Next\.js|asChild|apps/site.*src-tauri" AGENTS.md .tanstack .agents .codex 2>/dev/null` -> no conflicting instructions.

## STOP conditions

- TypeScript 7 is incompatible with desktop tooling. Do not downgrade desktop.
- Astro Check resolves TypeScript 7 despite its declared 5/6 peer boundary, or
  TypeScript 6 leaks into desktop. Stop rather than hiding the conflict.
- TanStack CLI cannot create a Router-only Vite SPA without adding TanStack Start
  or a server after consulting its pinned help.
- shadcn initializes Radix instead of Base UI and the pinned CLI offers no Base
  UI preset.
- A command wants to overwrite Plan 001 documents, `.git`, or `plans/`.
- Either app can import source from the other, or theme requires a runtime/framework dependency.
- Tauri debug build fails twice after fixing a clear prerequisite/config error.

## Maintenance notes

- Renovation is deliberate: update the ledger, both lockfiles, and CI together.
- Generated route and Paraglide files are never hand-edited.
- The CLI and Hotkeys packages are pre-1.0. Keep their APIs behind app-owned
  boundaries in later plans.
- Remove the site-only TypeScript 6 pin as soon as a verified Astro Check release
  supports TypeScript 7; never normalize the exception into a permanent policy.
